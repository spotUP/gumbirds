# Two-player co-op: implementation plan

Line numbers refer to branch `integ/beta1` (worktree `.claude/worktrees/beta1`) on 2026-11-16.

## Fixed owner decisions (not re-opened here)

- Co-op. Friendly stomps are on: a partner stomp pops one balloon and gives no score.
- Each player has own lives and own score.
- P2 joins at any time with P2 Start (costs one credit) and drops in by parachute from the top.
- The title already says "1 OR 2 PLAYERS" (`src/main.c:1087`).
- Camera follows the midpoint of both birds. Soft screen edges keep both on screen (arena 384 wide, screen 320).
- When one player loses the last life, the other plays on. CONTINUE shows over that player's HUD side. The run ends when both are out.
- v1 scope: arcade mode and its bonus stages. Gum Trip stays 1P. Arena: CORRECTED 2026-11-16 by owner, Arena is 2P versus per the reference (N8/D9 free-for-all, humans stomp each other); see ARENA-2P in todos.md.
- P2 colour is a palette swap (drafts: `thoughts/shared/drafts/2026-11-16-p2-colours/`). Assume one extra 16-colour palette slot.
- Rival count unchanged. Spawn pace faster in 2P.
- Budgets: sprite columns per line (arcade elements need exactly 15 of 15, `tests/host/test_sprite_budget.c:182-183`), vblank (demo and arena logic end near line 220 of 224, `make test-vblank`).

## Data model (reuse first)

- `Flier flier` becomes `Flier hero[2]`. Fighter index 0 and 1 are humans; cpus move to index 2.. in the pair pass (`HUMANS 2`, `n = HUMANS + cpu_count`, max 8: `uint8_t near[]` stays). Add `static_assert(HUMANS + STAGE_SPAWN_COUNT <= 8)` beside the bitmask.
- `ArcLives lives` becomes `ArcLives lives[2]`. Per-player score lives in `lives[i].score` (field already there). `g->score` stays as the P1 alias for Arena/Gum Trip and the flow, set from `lives[0].score` in arcade, so non-arcade code is untouched.
- Per-player `flaps[2]`, `cont_a[2]`, `start_in[2]`, `cont_start[2]`, `flier_steps` stays one counter (test sentinel).
- New `uint8_t players` (1 or 2) and `uint8_t joined` bit mask. A player is "in" while `lives[i].state != ARC_ENDED`.
- `game_step_arena(Game *g, uint8_t input)` keeps its signature; add `uint8_t input2` in `Game` (main.c sets it like `start_in`). Fewer call sites change than a new parameter (flow, demo, every host test).
- `over` = both players ENDED (1P: P1 ENDED, unchanged).
- AI: `ai_nearest` gets the humans array and count (`ai.h:33`), picks the nearer living human.
- Sound: `SE_WATCHED` gains one index; `prev_flaps`, `prev_life_state`, `prev_seconds` become `[2]`.

Phase 0 does this with `players = 1` and no behaviour change.

## Risks

- Vblank: two `flier_step`, AI target search over 2 humans, 8x8 pair pass. Logic already ends near line 220 of 224. Measure after Phase 1 and Phase 4; if over, move AI think to alternate frames per rival (already stateful) before cutting anything else.
- Sprites per line: P2 + chute adds 2-4 columns in the arena band. Arcade elements need 15 of 15 in their band; if P2 crosses that band the line drops sprites. Measure; do not guess.

- Demo and Arena/Gum Trip must stay byte-identical in behaviour: Phase 0 gates prove it; keep `players = 1` default in `game_reset`.
- Dead-body slots: only 2. Two humans plus rivals dying close together steal slots more often.
