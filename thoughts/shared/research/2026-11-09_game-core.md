# Game core

Files: src/core/{tuning.h, rng.[ch], game.[ch], hiscore.[ch]}, tests/host/{run.sh, test_core.c, knob_digest.c, knobs.txt}.
Run `tests/host/run.sh` (clang C99 -Wall -Wextra -Werror -pedantic, nice 19). Output goes to the scratchpad; prints a summary.
Not wired into the Makefile or main.c (owned by another job).

## Result

- Host: 3859 checks, 0 failures; 47 tuning knobs each proven to change a 40000-frame scripted run (override via -D); knobs.txt is checked against tuning.h so a new knob without an entry fails.
- Target: rng.c, game.c, hiscore.c compile with `m68k-elf-gcc -std=c99 -O2 -m68000 -ffreestanding -Wall -Wextra -Werror`. Unresolved symbols: `__udivsi3`, `__mulsi3` (libgcc; the 68000 has no 32-bit divide/multiply). Divisions are in the ramp code and run once per frame.
- Scripted run (seed 424242, hold A, never dodge): game over at frame 1541, score 1603, 6 kills, 100 shots, 10 overheats, 3 hits.

## Decisions

- Fixed point 8.8 for positions and speeds; whole pixels and frames elsewhere. No floats.
- No string.h in the core: the target gcc here has no libc headers in freestanding mode, so zero/copy are local byte loops (gcc may emit memset/memcpy calls; ngdevkit libc provides them).
- Hero hit box 26x36 (sprite 34x40), ducking 26x18. Shaved 4 px per side and 4 px off the top for fairness. Hero x is fixed at 48.
- Jump on B press (edge) from the floor only, not while ducking. Duck on C held, floor only. Peak jump about 61 px, air time about 35 frames.
- Obstacles: vent (jump), cable (duck; underside 28 px above floor), drone (shootable, head height), bot (shootable, floor). Enemies close in 0.5 px/frame faster than the scroll. Pool of 8; a spawn is skipped when full.
- Laser: A held fires every 8 frames, 4 bolts max, bolt y is 8 px under the hit box top (so ducking lowers the beam and it only reaches bots). Bolts pass through vents and cables. Heat 48 per shot, cools 3 per frame, full at 256 gives 90 frames lockout, then heat resets to 0. Holding fire overheats after about 11 shots.
- Score: distance points (1 per 8 px) + 200 x multiplier per kill + 50 per near miss. Multiplier = 1 + chain length, cap 5, chain window 120 frames, reset on a hit. Near miss: dodged hazard whose box came within less than 8 px of the hit box without touching, and no invulnerability overlap.
- Hit: lose a life, hazard removed, 120 invulnerability frames; 0 lives sets `over` and game_step becomes a no-op.
- Ramp (by distance): speed 2.0 to 5.0 px/frame (+1/256 per 64 px); spawn spacing 300 down to 170 px (-1 per 100 px) plus 0..79 jitter. Spawn is distance based, so faster scroll means more obstacles per second.
- Hiscore image: 130 bytes big endian: magic "ROOF", u16 version 1, 10 x {name[8], u32}, FNV-1a 32 checksum. insert returns the 0-based row, ties rank below existing scores, score 0 never inserts. Names are space padded.

## Exemptions

SCREEN_W, SCREEN_H (hardware), MAX_OBSTACLES (pool capacity) are not knobs. IN_D is unused by design.

## Open items

- Balance is untested by a human; all numbers are first guesses. Early game can spawn enemies immediately (no tutorial ramp of types).
- Reachability (real entry point driven in MAME) is not done; that needs main.c wiring.
- The seed value of 0 is replaced by a constant; the main loop should pass the frame counter at start press.
- No obstacle-vs-obstacle spacing guarantee beyond the minimum gap of 170 px; very tight cable-after-vent combos at speed 5 are possible but jumpable.
