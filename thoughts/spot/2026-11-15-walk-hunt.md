# WALK-HUNT report

## Q1: walk stalls at stage 3 on bac705a

Cause: commit 847d0d9 "Show the world in the attract demo and hold the result screen for a press", not DEMO-3 (0c9dd99).
- After stage 3 the bonus stage runs (ARC_BONUS_EVERY 3); the failing state is `arc=2` = ARC_BONUS (src/core/arcade.h:42).
- 847d0d9 changed src/core/result.c: the last result phase is now P_WAIT, `if (press) r->active = 0;` - no timeout.
- It taught the bonus path in tests/mame/arcade_check.lua to press A after RES_HOLD_FRAMES, but not the walk:
  `walk_wait_next` only waits for `g(O_ASTATE) == K.play` and never presses, so the result screen holds until the
  40000-frame watchdog. Log line: `BRAWL_TEST FAIL watchdog in phase walk_wait_next: flow=3 mode=2 stage=3 arc=2 lives=3 lstate=0`.
- 0c9dd99 only touches the attract demo path (flow.c demo branch, game_begin); it cannot hold a bonus result screen.
- b4cb950 predates 847d0d9, which is why the WORLD-1 walk (based on b4cb950) passed stage 3.

Fix (Lua, the layer with the bug; game behaviour is the owner's decision and stays): in `walk_wait_next`, tap A
(2 of every 8 frames, so each tap is a new edge) while the result screen is up (`b(O_RES) == 1`), release on PLAY.
Status: edited in the worktree, NOT committed, NOT yet run in MAME (build queue was blocked, see below).
